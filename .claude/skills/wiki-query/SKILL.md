# Wiki Query

> 用标签做索引快速定位相关笔记，只读"一句话"+"核心方法"两层回答 80% 的问题。控制 token 消耗。

## 触发

- 用户问跨论文的问题（如"HMR 方向有哪些时序平滑方法？"）
- 用户问某个标签下有哪些笔记

## 查询策略

### 层级 1：标签索引（~100 token）

用 `Grep` 搜 `_meta/index.md` 找对应 domain_tag 的条目。这一步回答"有哪些论文/笔记"。

### 层级 2：笔记摘要（~500 token）

读匹配笔记的 frontmatter + "一句话" + "核心方法"前两段。这一步回答"这些论文各做了什么"。

### 层级 3：深入（按需）

用户追问具体方法细节时，才读完整笔记。一般不需要。

### 不自动追链接

`related_notes` 是给用户点的导航入口，AI 回答时不追。除非用户说"把这几篇一起看看"。

## Token 控制

| 查询类型 | 做法 | 预期 token |
|---------|------|-----------|
| "X 领域有哪些方法" | grep index.md | ~200 |
| "某方法具体怎么做" | 读 2-3 篇笔记的前两层 | ~500 |
| "这几篇对比一下" | 并行读涉及笔记的前两层 | ~1000 |
| 深入追问 | 读完整笔记 | 按需 |
