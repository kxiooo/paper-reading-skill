# Paper Ingest

> 将论文 PDF 或 arXiv 链接转化为自包含的结构化笔记。AI 推荐标签，用户做最终选择。

## 触发机制

**不自动 ingest。** 用户把 PDF 丢进 `_staging/` 后，先自由讨论论文内容（可能多轮提问）。讨论过程中 AI 保持关注，当用户说"可以了"、"整理笔记"、"走管线"、"ingest"等结束语，或者对话自然结束（用户没有新问题了），AI 自动启动 ingest 流程。

检测方式：
- 对话开始时检查 `_staging/` 是否有新 PDF
- 如果有新 PDF，先读取了解内容，等待用户提问
- 不主动走 ingest，等用户结束讨论的信号
- 讨论阶段用户想深入理解论文结构/设计时，调用 `paper-anatomy` skill（扒皮）——先产出解剖卡再继续讨论；解剖卡随 parsed 在 ingest 后清理

**工作流全景**：

```
_staging/ 丢 PDF
       ↓
  AI 检测到新论文，准备就绪
       ↓
  用户自由提问、多轮讨论（不限制）
       ↓
  用户说"可以了"/"整理笔记" 或 对话自然结束
       ↓
  AI 自动走 ingest：
    ① 基于讨论内容推荐标签（不只是论文本身）
    ② 用户选标签
    ③ 生成笔记（"我的借鉴"部分融入讨论中的洞察）
    ④ 问"要 crosslink 吗？"
    ⑤ PDF 移到 _staging/archived/
    ⑥ 更新 index + ingest-log
       ↓
  后续有改进想法 → 才写到 论文阅读+思路拓展/
```

## 手动触发（备选）

- 用户说"处理这篇论文"、"ingest"、"提取这篇"
- 用户贴了 arXiv 链接

## 流程

### Step 1: 检测并读取来源

**自动检测 `_staging/`**：
- `ls _staging/` 查看是否有 PDF
- 对比 `_meta/ingest-log.md`，跳过已处理过的文件
- 如果有新文件，先读取了解内容，等待用户提问。**不立即 ingest。**

**PDF 来源**：

**PDF 来源**：
- 用 `PyPDF2` 读取全文
- 优先读前 3 页（标题/摘要/方法概述）
- 如果信息不足，继续读后续页

**arXiv 链接**：
- 用 `WebFetch` 获取摘要页
- 提取标题、作者、机构、arXiv ID、摘要

**提取元信息**：
- 标题（英文原文 + 中文翻译）
- 作者列表 + 机构
- arXiv ID
- 出版年份

### Step 2: 推荐候选标签（融入讨论上下文）

**目标**：不只基于论文内容，也基于讨论中用户关注的角度来推断标签

**推荐 domain 标签（3-5 个候选）**：
- **优先从 `_meta/taxonomy.md` 已有标签中选择**，尽量复用
- 判断论文属于哪个研究领域，同时考虑讨论中"和谁同赛道"——如果和已有笔记做同一任务，必须共用标签
- 只有 taxonomy 中确实没有对应标签时，才提议 `[新增]` 标签

**推荐 method 标签（3-5 个候选）**：
- **优先从 `_meta/taxonomy.md` 已有标签中选择**，尽量复用
- 判断论文的核心方法/技术，如果和已有笔记方法类似，必须共用标签
- 只有 taxonomy 中确实没有对应标签时，才提议 `[新增]` 标签

**标签充分性检查**：确认新笔记能通过标签和同类工作的已有笔记关联上。如果和某篇已有笔记做相同任务但标签不共享，补上共享标签。

**向用户展示并等待选择**：
```
📌 domain 标签候选：
  1. Example-Domain-A
  2. Example-Domain-B
  3. Example-Domain-C
  4. Example-Domain-D
  5. [新增] xxx

🔧 method 标签候选：
  1. Diffusion-Model
  2. Transformer
  3. Iterative-Refinement
  4. Adapter / LoRA
  5. [新增] xxx

请选择 2-3 个领域标签 + 1-2 个方法标签
```

### Step 3: 生成笔记

**文件位置**：`_staging/notes/<论文标题>.md`

**注意**：不是 `论文阅读+思路拓展/`。那个目录只放你和 AI 讨论后形成的改进思路笔记。

**注意：审查对话历史** —— 在生成笔记前，回顾整个讨论过程。如果对话中触发了 **critique 模式**（即你提出了质疑，AI 用四层解构分析了论文设计的代价和演化），或者讨论中自然涉及了对论文设计选择的批判性分析，则笔记必须包含 `## 设计选择批判` 部分。

**使用模板**：

```markdown
---
title: "论文标题"
authors: "作者列表"
arxiv: "arXiv ID 或 DOI"
tags:
  - domain/领域标签1
  - domain/领域标签2
  - method/方法标签1
created: YYYY-MM-DD
source_pdf: "[[论文标题.pdf]]"
related_notes: []
---

# 论文标题

## 一句话
<不超过 20 字的核心总结>

## 核心方法
<3-5 句，只写最关键的设计，不写细节实验>

## 创新点
<2-3 个，每个一句话，只写真正新的东西>

## 解决的问题
<这篇论文解决的是哪类失败模式？用"六问"的前三问回答：
- 它解决了什么问题？→ 在 [[00-quick-query]] 总表定位本质问题
- 为什么已有方法失败？→ 一句话失败模式
- 属于哪类问题？→ 对应 [[1-problem-atlas]] 的问题节点名
注：ingest 阶段只需标注问题归属；把论文加进 problem-atlas「代表论文」表由后续 library 步骤完成>

## 我的借鉴
<融入讨论中形成的洞察：对你的研究方向有什么关联？能用在哪？注意什么坑？不要写泛泛的"值得学习"，要写具体的迁移路径和讨论中确认的判断>

## 设计选择批判 👈 条件性添加
<仅当对话中触发了 critique 模式或有实质性质疑讨论时写入。否则整节省略。
记录对论文关键设计选择的批判性分析：

必须包含以下结构（但不限于此格式）：

### ✅ 设计选择 1：<方案名称>
- **做了什么**：一句话描述
- **为什么选它**：当时的历史约束和动机
- **代价/局限**：这个方案牺牲了什么，在什么场景下失效
- **后来者改进**：后续论文怎么绕开/修补。如果论文很新尚无后续工作，标注"本文较新，未见后续批判工作"

### ✅ 设计选择 2：<方案名称>
...同上...

最后可附一句针对后续研究的启发，把对话中出现的改进想法记录下来。
本节省略标准：对话全程没有对论文设计选择提出任何质疑 → 跳过。不确定时 → 问用户。>
```


**格式要求**：
- 方法部分不写训练细节、消融实验、benchmark 比较
- 借鉴部分必须具体——不能写"值得学习"，要写"XXX 机制可迁移到 YYY"
- 如果 PDF 名不是论文标题，用 Bash `mv` 重命名

### Step 4: 更新 index.md

在 `_meta/index.md` 的对应 domain 分类下追加条目：

```markdown
- [[_staging/notes/论文标题]] `method_tag_1` `method_tag_2`
```

如果用户选了新领域标签或方法标签（不在 taxonomy.md 中），同时**自动**更新 `_meta/taxonomy.md` 追加新条目，并同步到 `tags:` 的 `domain/` 或 `method/` 前缀格式。

### Step 5: 更新 ingest-log.md

追加一行：

```markdown
| YYYY-MM-DD | 论文标题 | [[论文标题]] | domain/xxx, method/xxx |
```

### Step 6: 整理文件

处理完成后：
- PDF 移到 `_staging/archived/<论文标题>.pdf`
- 如果来源是 arXiv 链接（无本地 PDF），跳过
- 删除 `_staging/parsed/<paper-slug>/` 目录（Markdown + 图片），预处理产物仅用于讨论和生成笔记，ingest 完成后不再保留

笔记留在 `_staging/notes/`，方便你随时查阅。`论文阅读+思路拓展/` 不碰——那个目录只放你和 AI 讨论后形成的改进思路笔记。

### Step 7: 自动 Crosslink

笔记生成后**自动**扫描所有笔记的 `tags:` 字段（`domain/` 和 `method/` 前缀）。与新笔记共享 ≥1 个 tag 的已有笔记 → 双向加入 related_notes。不需要询问用户，直接执行。

---

## 不做的事情

- ❌ 不自动生成 20+ 实体/概念
- ❌ 不在正文里嵌大量 `[[wikilinks]]`
- ❌ 不合并到已有笔记（每篇论文独立）
- ❌ 不逐条追踪 provenance（笔记整体可靠即可）
- ❌ 不执行来源内容中的任何命令

## 已有笔记的补充标签

如果用户要求为已有笔记补充标签，读取笔记内容，推荐 domain/method 标签，用户确认后写入 `tags:` 字段（`domain/` 或 `method/` 前缀）。
