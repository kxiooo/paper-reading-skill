# Paper Anatomy — 论文解剖（扒皮）

## 定位

ingest 阶段（论文已读完、笔记还没定稿前）的**深度理解协议**。

**目的**：不是给论文分类、不是为 library 做前置，而是把论文**扒透**——搞清楚它为什么做、架构每个组件干什么/输入输出是什么/和别的设计差在哪、哪些环节是赌注。解剖的深度决定后面讨论和笔记的质量。

**与 library 的关系**：独立。解剖卡不入库、不分类。library 是另一条事后管线，顶多"可选参考"解剖卡。

## 触发

- 用户说："扒皮 / 解剖 / 拆深一点 / 深入拆解"
- AI 读完论文、准备进入深入讨论时，可主动提出先走解剖

## 管线位置

```
PDF → OpenDataLoader 预处理 → 扒皮（本 skill，产出解剖卡）→ 用户讨论 → ingest 生成笔记 → 用户满意后再说 library
```

## 前置条件

- 论文必须已经过 OpenDataLoader 预处理（见 CLAUDE.md，禁止直接 Read 原始 PDF）
- 解剖卡写入 `_staging/parsed/<paper-slug>/anatomy.md`（工作底稿）
- ingest 完成后随 parsed 目录一起清理（如果用户想保留，改路径到讨论区）

## 解剖卡模板

对每篇论文，按以下结构产出解剖卡。**每个组件都要单独一节**，不要堆在一段里。

```markdown
# 解剖卡：<论文标题>

## 0. 一句话本质
<这篇论文最内核的单一贡献，≤20字，不用术语>

## 1. 任务与问题定位（理解，不是分类）
- **任务定义**：输入是什么 → 输出是什么？（形式化）
- **声称的失败**：论文说已有方法为什么不行？（引用它的逻辑链，不是我们的猜测）
- **核心思路**：它用一个什么思路绕开/解决上面的失败？一句话

## 2. 架构数据流解剖
整体数据流：输入 → 组件A → 组件B → … → 输出

### 组件A：<名字>
- **职责**：它负责什么（一句话）
- **输入**：什么格式 / 从哪个组件来
- **输出**：什么格式 / 送到哪个组件
- **关键设计**：为什么这么设计？不这么做会怎样？
- **分工边界**：它明确不做 X——X 由哪个组件承担？（同一篇论文内部）
- **与相似组件的差异**：库中/已知方法的对应组件差在哪（输入？表示？损失？推理？）

### 组件B：<名字>
…（同上，每个组件一节）

## 3. 关键设计质询
对每个"非显然"的设计，问一句（选最重要的 2-4 个写）：
- 核心假设是什么？假设不成立会怎样？
- 哪些设计是必须的，哪些只是顺手选的（可替代）？
- 有没有"说得通但没验证"的环节？
- 换掉某个组件，系统还成立吗？

## 4. 与最接近方法的本质差异
<一句话定位：和库里最近的方法相比，差异发生在哪个环节——输入？表示？损失？推理策略？>

## 5. 可攻击点 / 风险清单
<1-3 条，供 critique / 后续深入讨论当弹药>
```

## 组件解剖规范（第 2 块的核心纪律）

解剖架构时**必须**做到：

1. **输入/输出要精确到"什么格式/维度/从哪来到哪去"**，不能写"处理特征"这种废话。
2. **分工边界要写"它不做 X"**——同一篇论文里 A 和 B 容易混淆时，必须说清 A 不干什么、那部分由谁做。
3. **差异要对比到具体环节**——和库中已知组件的差异，落到"输入不同 / 表示不同 / 损失不同 / 推理不同"四个档位之一。
4. **每个组件独立成节**，不许一段话带过多个组件。

## 深度质询问题清单（第 3 块，问得深的保障）

按需选取，不硬凑：

- 如果去掉这个模块，效果会退化多少？论文有没有消融证明它是必须的？
- 它的"地基赌注"在哪一环？（比如 UniEdit-Flow 赌"flow 轨迹直线可复用速度"，FSQ 赌"固定网格够用"）
- 训练和推理时行为一致吗？（有没有 teacher-forcing / 分布偏移 / 误差累积的坑？）
- 这个方法卡在哪个环节的哪个假设上？换一个任务（动作→图像）哪个假设先崩？
- 它的组件和基线方法的组件，本质是同一个东西换了个名字，还是真的不同？
- 论文报告成功的 benchmark，是否恰好避开了它的弱点？

## 输出格式要求

- 解剖卡用**可复制的 markdown**（用户可能直接粘贴进讨论或自己的笔记）
- 提到库中已有论文/机制时，用双链：`[[_staging/notes/...]]` 或 `[[2-mechanism-atlas#...]]` 风格（与库编号一致）
- 大白话优先，术语次之——解剖卡是给人读懂的，不是给人收藏的

---

## 与 paper-ingest 的关系

- 解剖卡是 ingest 笔记的原料：
  - `## 核心方法` ← 第 2 块组件职责
  - `## 创新点` ← 第 3 块质询后确认的"真新"部分
  - `## 我的借鉴` ← 第 4 块差异 + 第 5 块风险
  - `## 解决的问题` ← 第 1 块
- ingest 完成后解剖卡随 parsed 清理，不留重复资产
